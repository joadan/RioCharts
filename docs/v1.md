# Version 1.0

What 1.0 is, what it needs, and what waits. Decisions are marked **Decided**; the rest is the
working list.

## What 1.0 promises

1.0 is a stability promise, not a feature milestone: after 1.0, upgrading within 1.x does not
break code that uses the public API, and does not break saved JSON chart definitions. Breaking
changes wait for 2.0. Before 1.0 the APIs still change freely (see the status note in the README).

## Decisions

| Topic | Decision |
|---|---|
| Scene and Layout types | **Decided:** internal. Renderers (Blazor, Skia) reach them through `InternalsVisibleTo`; custom renderers are not a 1.0 extension point. Reverses "the scene types are public" in implementation-notes (Public API surface). |
| Packages | **Decided:** all five ship as 1.0 and public: Core, Blazor, Skia, AI and Mcp. |
| Animations | **Decided:** not in 1.0, and maybe never. The entry fade stays; update animations stay out as Design.md says (reasons in implementation-notes, Animation). |
| Canvas series layer | **Decided:** stable in 1.0. The API is only `SeriesLayer.Canvas`; where it behaves differently from SVG is documented (see below). |
| Freeze | **Decided:** short, about a week: only fixes and non-breaking additions, then tag 1.0. |

## Before the freeze

### Public API
- ~~Make `Scene` and `Layout` internal, plus anything else in Core that only renderers use.~~
  Done (scene, layout, path builder, text measurers, Skia's renderer types), and in the API review
  also the scales, formatters, map projections, data helpers and riocharts-mcp's server types.
- One naming and shape pass over everything that stays public (all five packages): names that
  clash with common libraries (as `SortOrder` did), consistent parameter names across series,
  nothing public that is only there for tests.
- Name clashes with other Blazor libraries (checked 2026-11-24, kept for now, decide before the
  freeze). A type with the same name and arity in two namespaces that an app imports both of
  fails to compile with CS0104 wherever it is used unqualified. `RioCharts.Blazor` and
  `RioCharts.Core` are the usual `_Imports.razor` lines; `RioCharts.Core.Definitions` is not.

  | RioCharts type (namespace) | Also in | Impact | Possible rename |
  |---|---|---|---|
  | ~~`SelectionMode`~~ (Blazor) | `MudBlazor.SelectionMode` (9.14) | High: both namespaces sit in `_Imports.razor` of a MudBlazor app | **Done:** renamed to `ChartSelectionMode` |
  | `LegendPosition` (Core) | `ApexCharts.LegendPosition` (6.1) | Medium: while migrating from ApexCharts | `ChartLegendPosition` |
  | `SeriesType` (Core) | `ApexCharts.SeriesType` | Medium: same | `ChartSeriesType` |
  | `LabelPosition` (Core) | `ApexCharts.LabelPosition` | Medium: same | `ChartLabelPosition` |
  | `FieldType` (Core.Definitions) | `MudBlazor.FieldType` | Low: `Definitions` is rarely imported in Razor | `DataFieldType` |

  No clash: `ChartPoint` and `TimeValue` (MudBlazor's are generic, `ChartPoint<T>` and
  `MudBlazor.Charts.TimeValue<T>`, so C# tells them apart). TabBlazor 1.7.63-beta (used internally):
  no clashes; its `TabBlazor.SortOrder` was the reason for the `ChartSort` rename. Not checked yet:
  Radzen, Syncfusion, Blazorise, Fluent UI.
- Series parameters (reviewed 2026-11-24, all 22 series components). Conventions: a function
  of the item ends in `Value` (`XValue`, `LowValue`, `TargetValue`); a fixed value has no suffix
  and pairs with its function (`Target` / `TargetValue`, `Error` / `ErrorValue`); a shared idea
  has one name (`InnerRadius`, `StartAngle`, `Max`, `Midpoint`, `Bucket`, `MarkerSize`); chart
  events are `On...` (happened), `On...ing` (cancelable) and `...Changed` (binding).
  - Done: `MapBubbleSeries.Latitude`/`Longitude` renamed to `LatitudeValue`/`LongitudeValue`.
  - Kept on purpose: `WaterfallSeries.IsTotal` (a predicate reads as a question), and
    `PieSeries.GroupSmallSlices` next to `TreemapSeries.GroupSmallItems` (each fits its chart;
    JSON's `groupSmallSlices` covers both).
  - Gaps for 1.x (non-breaking): a `Min` for the color scale of heatmap, calendar and map (it
    starts at the lowest value), `MaxBarWidth` on waterfall, histogram and range bar.
- ~~Lock the surface: public API baselines~~ Done: `PublicApiAnalyzers` with a
  `PublicAPI.Shipped.txt` per library package (1,816 symbols at the start); an unlisted change
  fails the build (CONTRIBUTING.md, Public API). After 1.0, package validation against the 1.0
  packages as well.

### Canvas layer
- ~~Document where it differs from SVG.~~ Done: "Canvas compared with SVG" on the docs site's
  Large data page (labels and annotations under the series, no highlight, no entry fade, more

### Behavior
- ~~Accessibility pass on every chart type.~~ Done 2026-11-24 on the render-mode app's
  "Every chart type" page (`await rioKeys()`), all 23 types, Interactive Server: each chart has
  role `application`, a label, a description and a tab stop; ArrowRight, ArrowDown and End move
  through points and announce "value, 2 of 4" in the live region; the tooltip follows and
  Escape closes it. Focus rings on the chart, legend items, annotations and treemap/map
